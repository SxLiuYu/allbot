## 一、这是什么

一个仓库装三种形态：

| 目录      | 是什么                   | 技术栈                      | 规模                        |
| --------- | ------------------------ | --------------------------- | --------------------------- |
| 根目录    | AllBot 主动认知服务器端  | Node 22 / TypeScript / pnpm | 9625 个文件                 |
| `mobile/` | 言出（Mika）Android 应用 | Kotlin / Gradle / Compose   | 2282 个文件，606 个测试文件 |
| `voice/`  | Charlie 语音硬件端       | Python 3.12 / FastAPI       | 636 个文件，125 个测试文件  |

三者是 vendored snapshot 合进一个仓库的（见 `VENDOR.md`），不是独立 submodule。

## 三、这一轮修了什么

### 三类真 bug（不是测试问题）

共同特征：**异常被 `except Exception` 静默吞掉，功能完全不生效，日志只留一句 debug**。

1. **早晨问候与 `suggest_action` 从未执行过**
   `app/schedulers.py` 只定义了 `hour`，没定义 `minute`，但分支条件写的是
   `hour == 7 and minute == 30`。每轮抛 `NameError` 被外层捕获。

2. **时间/位置/天气/用户状态/待办整段没进系统提示词**
   `agent/context.py` 的 `format_context_for_prompt` 不收 `uid`，而
   `agent/system_msg.py:472` 传了 `uid=uid`。TypeError 被吞。

3. **人格段、偏好注入、"我住在X"写入长期失效**
   同类型的签名不匹配，涉及 `agent/persona.py` 三个函数和
   `agent/preferences.py` 三个函数。

修法统一是**补上 `uid` 参数**（接受并透传），不是删掉调用方。原因：`uid` 将来
要用于多用户隔离，删了调用方等于把这条路堵死。

### 两个孤儿模块补齐接线

代码完整但零引用，等于没做：

- **`app/runtime_settings.py`** → 新增 `GET/POST /api/settings`，OTA 响应新增
  `device` 段。设备 OTA 地址不再编译进固件，服务器搬家可以提前下发。
  详见 `voice/docs/SETTINGS-AND-KEYS.md`。
- **`agent/stepfun_keys.py`** → `STEPFUN_KEY` 支持逗号分隔多把，接入 TTS / LLM /
  管理页校验三处。429 短冷却、401/403 长隔离、全冷却兜底不阻塞。同一份文档里有。

### 发布链路（改了三轮才对）

包名从 `allbot` 改成 scoped 的 `@sxliuyu/allbot` 后，`npm pack` 产出的是
`sxliuyu-allbot-<ver>.tgz`，但 4 处还按 `allbot-<ver>.tgz` 匹配：

- `publish-tarball.yml`：tarball 变量为空 → `gh release create` 缺文件参数失败
- `src/commands/android-install.ts`：找不到 asset → 静默回退到 npm 全局安装
- `scripts/install.sh` / `install-termux.sh` / `release.sh`：下载链接 404

**第二轮我自己引入了新 bug**：写成 `ls a-*.tgz b-*.tgz`，只要有一个通配符没
匹配到，`ls` 就 exit 2，`pipefail` + `set -e` 让整步失败（日志里是
`Process completed with exit code 2`）。最终改用 `find` 逐条筛选。

### 两个 flaky

- **gateway helper 超时**：`onceMessage` 和 `waitForWebSocketOpen` 默认 10 秒，
  full-suite 跑 581+ 文件时 event loop 饱和会偶发超时。提到 30 秒，失败信息
  带上实际等待时长。
- **TTS 冷却测试**：硬编码"链上 3 个 provider、共 4 次调用"，我加了 `local`
  provider 后链变长就挂。改成按实际链长推导。

## 四、待办

### 1. npm 发布（阻塞，缺凭证）

`publish-npm` job 现在是 skipped，由仓库变量 `PUBLISH_NPM` 控制。当前没有设
任何变量和 secret。

两条路，任选：

- **token 方式（快）**：npmjs.com → Access Tokens → Granular Access Token，
  勾 Read and write + Automation（绕过 2FA）。存成仓库 secret `NPM_TOKEN`，
  再把 `PUBLISH_NPM` 设成 `true`。
- **OIDC 方式（标准）**：npmjs.com 包设置页 → Trusted Publisher，填
  repo `SxLiuYu/allbot`、workflow 文件名 `publish-tarball.yml`（要过 2FA）。
  然后设 `PUBLISH_NPM=true`。

workflow 两种都支持，有 `NPM_TOKEN` 就优先用它。

包名 `@sxliuyu/allbot` 目前 npm 上还不存在（registry 返回 404）。

### 2. 分支保护要不要强制走 PR

现在直接 push main 不会被拦。要强制走 PR 需要开
`required_pull_request_reviews`——但开了之后你自己推 main 也会被拦，得先开分支
提 PR。这个取决于你的工作习惯，我没擅自开。

### 3. FR-14 多用户隔离（247 条 xfail 的根源）

`voice/charlie` 现在偏好、人格、记忆都是**单文件单用户语义**。我修签名时给
`uid` 参数留了位置（接受但暂不参与分片），注释里写明了将来在这里接上即可，
调用方不用再改。

这是一整块特性，不是修 bug 的量级。

### 4. 8099 TTS 输出长度抖动（另一个会话在处理）

Mac 局域网 TTS（moss-tts-nano）同一句文本连续请求，返回长度在 **0.48s 到
15.76s** 之间无规律波动，非流式端点同样抖。是服务侧问题。在修好之前
`LOCAL_TTS_STREAM_URL` 建议留空走非流式。

详见 `voice/docs/LOCAL-REALTIME.md` 末尾。

### 5. 两个无 release 的死 tag

`v2026.11.15` 和 `v2026.11.16` 留在远端但没有对应 release：

- 前者指向 tarball 修复之前的 commit
- 后者被 `exit code 2` 挡住

它们是真实历史，我没删（删 tag 是破坏性操作）。要清理的话自己决定。

## 五、环境与踩坑

### 本机（Windows）能做什么、不能做什么

**能**：改代码、跑 `pnpm check` / `pnpm format:check` / `config:docs:check`、
单文件语法检查、用 WSL 跑 voice 全量测试。

**不能**：

- **根目录 vitest 跑不起来**：报 `Cannot find module '/@id/C:/...'` 或
  `ERR_MODULE_NOT_FOUND`。这是 Windows 本地配置问题，CI 的 Linux 没这毛病。
  所以根目录测试只能靠 CI 验证。
- **没有 JDK**：无法本地构建 Android。
- **没有 libopus**：11 个 voice 测试文件在 Windows 上收集阶段就失败（`Could not
find Opus library`）。这是平台差异，不是真失败。
- **github.com:443 不通**：只有 `ssh.github.com:443` 和 `api.github.com` 通。
  所以 git 用 `ssh://git@ssh.github.com:443/SxLiuYu/allbot.git`，管理用 API。
  下载 release asset 也不行（重定向到 `objects.githubusercontent.com` 打不开）。

### 用 WSL 跑 voice 全量（推荐，能复现 CI）

```bash
# 一次性准备
wsl.exe -d Ubuntu-24.04 -- bash -lc 'python3 -m venv /tmp/voiceenv'
wsl.exe -d Ubuntu-24.04 -- bash -lc \
  'cd /mnt/c/allbot-public/voice/charlie && \
   /tmp/voiceenv/bin/pip install -q -i https://pypi.tuna.tsinghua.edu.cn/simple \
   -r requirements.txt -r requirements-dev.txt'

# 跑测试（必须先把 .sh 的 CRLF 转掉，否则 shell 脚本类测试会假失败）
wsl.exe -d Ubuntu-24.04 -- bash -lc \
  'cd /mnt/c/allbot-public/voice/charlie && \
   find . -name "*.sh" -exec sed -i "s/\r$//" {} + && \
   ALLBOT_TEST_MODE=1 /tmp/voiceenv/bin/python -m pytest tests -q --tb=no'
```

**WSL 没有外网到 pypi.org**，必须用清华镜像。github.com 也不通，但 api 通。

### 格式化用 oxfmt，不是 prettier

`pnpm format:check` 走 `oxfmt`。用 `npx prettier --write` 反而会把文件改坏
（两者对长行字符串拼接的换行策略不同），下一轮 CI 直接挂。这条踩过。

```bash
npx oxfmt <file>        # 改
npx oxfmt --check <file> # 验
```

### 改 voice 测试的注意事项

- **`tests/test_memory_store.py` 曾在导入期写 `CHARLIE_USER_ID`**，污染整轮
  测试：所有后续用例的 persona/preferences 都写到 `*_test_user.json`，
  断言 `persona_state.json` 的用例报 FileNotFoundError。现在改成用 fixture
  按用例隔离，别改回去。
- **`agent.context` 有 60 秒 TTL 缓存**。测试里断言"调用了 `_load_reminders`"
  必须先清 `_context_cache`，否则前面用例烤进去的空上下文会让它不调用。
- **provider 链长不是常数**。写测试别硬编码"N 次调用"，按
  `asr_tts.TTS_PRIORITY` 实际推导。
- **平台相关分支要 patch 平台**。`agent/vision.py` 的 `screencapture` 只在
  Darwin 走，Linux CI 上要 `patch.object(vision_mod.platform, "system",
return_value="Darwin")`。

### workflow 的 YAML 坑

- **不要在 `run: |` 里写 heredoc**：左对齐即结束块，缩进进去又会
  `IndentationError`。脚本放 `scripts/` 下用文件调用。
- **`ls a-*.tgz b-*.tgz` 在任一遍配符不匹配时 exit 2**。用 `find`。
- **push 的 `paths` 与 `tags` 是 AND 关系**。写了 `paths` 之后，tag push 也
  必须改动这些路径才触发。想 tag 触发就别写 `paths`。
- **job log 需要 admin 权限才能通过 API 读**（匿名 403）。所以 CI 里用
  `::error title=X::msg` workflow command 发 check-run annotation，那个匿名
  可读。GitHub 每步最多 10 条 annotation，脚本里限了 6 条 + 汇总行。
  `scripts/pytest-junit-to-annotations.py` 和
  `scripts/gradle-failures-to-annotations.py` 就是干这个的。

## 六、常用命令

```bash
# 本地检查（能跑，快）
pnpm check                 # tsc + 各种静态检查
pnpm format:check          # oxfmt
pnpm config:docs:check     # 配置文档基线

# release 流程（scripts/release.sh 会 bump 版本 + build + commit + tag + push）

# 手动发 APK（不等 mobile/ 变更）
# GitHub → Actions → Build Android APK → Run workflow
```

1. 写 `docs/releases/v<版本>.md`（**必须在打 tag 之前提交**，workflow 读的是
   tag 指向的 commit 快照）
2. 检查 release 正文不是空壳
